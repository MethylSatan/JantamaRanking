# 031 雀魂アカウントを表示用 ID なしで指定できるようにする

状態: todo / 依存: 024、026

## 目的
ランキングの雀魂アカウントは、今は表示用 ID（フレンド申請に使う番号）でしか指定できない。主催者は配信者であることが多く、表示用 ID は気軽に人に教えるものではない。しかも今の作りでは、表示用 ID が DynamoDB の項目のキー（`ACCOUNT#<表示用 ID>`）に残り、管理の画面でそのランキングの Host 全員に見え、操作ログにも書かれる。表示用 ID を聞かず、持たずに済むようにする。

## 読むべき資料
- `docs/architecture.md`「データモデル」「API」「取り込みの手順」
- `src/api/routes.ts`・`src/api/store.ts`・`src/api/jobs.ts`・`src/api/games.ts`・`web/src/RankingPage.tsx`（`displayId` を使う所。2026-11-27 時点で約50か所）

## 作業範囲
- 仕組みの上では内部 ID だけで足りる。雀魂への要求は内部 ID で行っていて、表示用 ID は最初の候補の更新で内部 ID を引く（`searchAccountByEid`）ためだけに使っている
- 内部 ID は、その人が参加した対局の牌譜（head の `accounts`）や候補の参加者から分かる。指定の仕方を決める。候補は次のとおり
  - 内部 ID を入れる（Admin 向け。内部 ID はゲームの画面には出ない）
  - 取り込み済みの対局・候補の参加者から選ぶ（Host でも使える。ただし、最初の1人はほかの方法で指定する必要がある）
  - 表示用 ID は入力の手段としてだけ残し、内部 ID を引いたら保存しない
- ランキングの雀魂アカウントの項目のキーを内部 ID にする。画面の表示は一覧に出ていたニックネーム（`MAJSOUL#<内部 ID>` の名前）にする。操作ログの対象も同じ
- 既存の項目の移し替え（2026-11-27 時点で、本番の雀魂アカウントの項目は、削除した動作確認用のランキングにしか無い）
- 表示用 ID を誰がどこで見られるかを `docs/architecture.md` に書く

## 完了条件
- 表示用 ID を知らなくても、ランキングに雀魂アカウントを指定して候補を更新できる
- 表示用 ID で指定した場合も、表示用 ID が保存・表示されない（残すと決めた場合は、その理由が記録されている）

## メモ
- 2026-11-27 タスク 015 の後に起票。ちのリーグに主催者の雀魂アカウントを指定しようとして、表示用 ID が手元に無かった。ユーザーの指摘: 配信者は表示用 ID を気軽に公開しない
