## 目的
**前提（2026-11-16）**: 目指す形はセルフサービスの Web サービス（`docs/product.md`）。このツールは、そのサーバー側の部品として使えるように作る。ログインは L2 が前提で、L1 は最終手段。
運営のアカウントで、主催者の友人戦の一覧と中身を取り、ランキングの取り込みに使える牌譜 json を出力するツールを作る。主催者に作業を求めない。

  - 使えたら、PaifuImporter の確認（`npm install`、`env.js` とトークンの取り方）も行う（001 から移した）

- ~~主催者の1回の企画あたりの対局数を確認する~~ → 10〜30局。企画ごとに、遅くとも2回に1回は取りに行く（`docs/decisions.md` 2026-11-16）
- 流れ: 主催者の表示用 ID → `searchAccountByEid` → `fetchAccountInfoExtra`（四麻 `category=1`・三麻 `category=2`、`type=2`）→ 取り込み済みでない対局を**候補として一覧で出す（日時・ルール・参加者）→ 運営が選んだ対局だけ** `fetchGameRecordsDetail` → 既存の `parse()` 相当で牌譜 json に変換して出力
  - 自動では取り込まない。主催者の友人戦には、ランキングの対象でない対局もある。選ぶのは、Web サービスの画面で利用者が行う想定（画面はタスク 008 の結論に従う）。それまでの間の選び方（ファイル指定など）は、実装の計画で決める
- 取り込み済み（と、対象外にした）の uuid を手元に記録し、二度出さない。50件の上限に近づいたら警告する
- 主催者の ID、取り込み済みの記録、ログイン状態のプロファイルはコミットしない（`local/` か gitignore 済みの場所に置く）
- 要求の間隔を空ける（検証では2秒）
- 検証用の試作 `local/probe/probe.js`（gitignore 済み。Playwright の環境の作り方は 001 のメモ）を土台にしてよい。リポジトリに入れるコードには、主催者の ID などを書かない
- 運営は非エンジニアとは限らない前提で、実行手順を短くする（`docs/product.md` の非機能要件との関係を整理する）
