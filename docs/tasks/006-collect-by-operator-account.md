# 006 運営アカウントでの牌譜回収ツールの実装

状態: todo / 依存: 005

## 目的
運営のアカウントで、主催者の友人戦の一覧と中身を取り、ランキングの取り込みに使える牌譜 json を出力するツールを作る。主催者に作業を求めない。

## 読むべき資料
- `docs/tasks/005-paifu-collection-method.md`（検証結果、方式とログイン方法の比較）
- `docs/architecture.md`（雀魂の WebGL 版の通信、PaifuImporter の詳細）

## 作業範囲
- **最初に**ログイン方法をユーザーに選んでもらう（005 の比較。推奨は L1: ブラウザでログインし、ゲームの接続に相乗りする）。決定は `docs/decisions.md` に書く
  - L2 を選んだ場合は、PaifuImporter の確認（`npm install`、`env.js` とトークンの取り方、`getPaifu.js` で1件取得）も行う（001 から移した）
- 主催者の1回の企画あたりの対局数をユーザーに確認し、取りに行く間隔の目安を決める（四麻・友人戦の一覧は最新50件まで）
- 流れ: 主催者の表示用 ID → `searchAccountByEid` → `fetchAccountInfoExtra`（四麻 `category=1`・三麻 `category=2`、`type=2`）→ 取り込み済みでない uuid だけ `fetchGameRecordsDetail` → 既存の `parse()` 相当で牌譜 json に変換して出力
- 取り込み済みの uuid を手元に記録し、二度取りしない。50件の上限に近づいたら警告する
- 主催者の ID、取り込み済みの記録、ログイン状態のプロファイルはコミットしない（`local/` か gitignore 済みの場所に置く）
- 要求の間隔を空ける（検証では2秒）
- 検証用の試作 `local/probe/probe.js`（gitignore 済み。Playwright の環境の作り方は 001 のメモ）を土台にしてよい。リポジトリに入れるコードには、主催者の ID などを書かない
- 運営は非エンジニアとは限らない前提で、実行手順を短くする（`docs/product.md` の非機能要件との関係を整理する）

## 完了条件
- 運営が1コマンド（＋必要なときだけブラウザでログイン）で、主催者の新しい友人戦の牌譜 json を得られる
- 既存の取り込み先（当面は Drive → GAS）に渡せる形式であることを確認している
- 手順が `docs/` に書かれている
