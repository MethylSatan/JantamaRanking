# 007 Node から直接ログインする方法（L2）の調査

状態: todo / 依存: 005

## 目的
**Web サービスにするための前提条件**（`docs/product.md` 目指す形）。L2 ができなければ、L1（ブラウザ相乗り）が最終手段になり、Web サービスにはできない。
牌譜の回収ツール（タスク 006）を、ブラウザを使わず Node だけで動かせるかを決める。2026-11-16 の最初の検証では Node からのログインが `err=151` で失敗し、途中で止めた。その続き。

## 読むべき資料
- `docs/tasks/006-collect-by-operator-account.md`（メモ: 最初の検証）
- `docs/architecture.md`（雀魂の WebGL 版の通信。ログインの流れ）
- `docs/local/006-l2-verification-notes.md`（ローカル限定。使ったスクリプト、試したこと、アカウントの状態）

## 作業範囲
- **始める前に**、検証用のアカウントの状態をユーザーに確認する（メール認証でログインし直したか、自動ログインが戻ったか）
- `err=151` の原因を、ブラウザの接続と Node の接続の違いから探す。候補は次のとおり
  - 接続時の HTTP ヘッダー（Origin・Cookie・User-Agent など）
  - 接続前の `/api/clientgate/routes`・`upgrade_info`
  - `oauth2Auth` の `code` が、Yostar 側でブラウザの端末 ID などに結びついている可能性
- Node だけでは通らず、Yostar の API の署名（`Sign`）を再現する必要がある場合は、解析に進む前にユーザーに相談する（規約の面での判断が要る。判断は `docs/local/` に書く）
- 試すたびに、アカウントに影響が出ていないかを確かめる。失敗が続いたら繰り返さずに止める
- サーバーで動かし続ける前提で確かめる: 認証情報（`code` / `uid`）をどれくらいの期間使えるか、取り直すのにブラウザやメール認証が要るか
- 結論（L2 で行く / 最終手段の L1 にする）を `docs/decisions.md` に書き、タスク 006・008 を進められる状態にする

## 完了条件
- ログイン方法が決まり、`docs/decisions.md` に書かれている
- L2 の場合は、Node だけでログインから牌譜の中身の取得まで通ることを確認している
