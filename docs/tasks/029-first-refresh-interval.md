# 029 初めての候補の更新が続けて受け付けられる

状態: todo / 依存: 025

## 目的
同じランキングへの候補の更新を短い間に続けて送ると、雀魂アカウントの内部 ID がまだ無い（そのランキングで初めての更新）ときは、どれも受け付けられ、ジョブごとに雀魂へログインする。雀魂に余計な負荷をかけないよう、初めての更新にも間隔の確認を効かせる。

## 読むべき資料
- `src/api/routes.ts` の `refresh`（内部 ID が無いアカウントは `reserveRefresh` を数えない）
- `docs/architecture.md`「API」「雀魂に負荷をかけない運用」

## 作業範囲
- 内部 ID が無いアカウントでも、短い間の二重の受け付けを防ぐ（例: ランキングと表示用 ID で予約する、そのランキングで未完了の更新のジョブがあれば 429 にする）。どの形にするかはこのタスクで決める
- 管理の画面のボタンが押せる間（処理の待ち）に二重に送れないかも確かめる

## 完了条件
- 初めての候補の更新を続けて送っても、雀魂へのログインが1回で済む（自動テストで確かめる）
