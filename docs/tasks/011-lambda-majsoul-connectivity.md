## メモ
### 2026-11-19 1日目: Lambda から1回試行 → err=151
- 進め方はユーザーと相談して決めた。Lambda からの試行は Node でのログイン1回だけで、009 の 11/17 の計測と同じ操作なので、今日行った。同時ログインの確認は、ブラウザの自動ログインで Token が更新されるおそれがあるので、11/23 の計測の後に回す
- 使い捨ての Lambda（`ap-northeast-1`、nodejs22.x、256MB）を CLI で作り、`node-direct.js` と同じ手順（Yostar の API は呼ばない）を1回実行した。認証情報は invoke の payload で渡し、zip・環境変数・ログには入れていない
- 結果: clientgate（HTTP 200）、ゲートウェイへの接続、`requestConnection`（err=0）、heartbeat は通った。**`oauth2Auth` が err=151** で止まった。再試行はしていない
- 送った `oauth2Auth` の本体は、ブラウザの記録（009 の run12）とバイト単位で一致した。要求の中身の誤りではない
- 手元で通ったときとの違いは、接続元の IP（AWS）、Node の版（22 と 26。TLS の指紋が違う）、前回の使用からの日数の3つ。どれが原因かは未確定（`docs/decisions.md` 2026-11-19 タスク 011）
- 後片付け済み: 関数・ロググループ・実行ロールを消し、消えたことを確かめた
- 具体（時刻、保存したファイル）は `docs/local/006-l2-verification-notes.md`

### 同日 21:30: 手元からも err=151
- ユーザーの許可を得て、手元（Node 26）から `check-cred.js` を1回実行した → `oauth2Auth` が同じ err=151。認証情報が今は通らない。Lambda の失敗は、Lambda 側の条件によるものとは言えなくなった（`docs/decisions.md` 2026-11-19 タスク 011）

### 同日 21:38〜21:41: 原因は版の古さ
- 認証情報の取り直しを自動化した（`local/probe/cred-refresh.sh`: 確認 → ブラウザで取り直し → 再確認。`login-observe.js` に `AUTO=1` を足し、60秒でログインが終わらなければ画面を記録して HTML のログインボタンを1回押す）。1回実行すると、ブラウザは操作なしで自動ログインでき、ゲームは**同じ `code` / `uid` で通っていた**
- ゲームが送る版は `WebGL_2022-0.16.287`。こちらは `0.16.280` を固定で送っていた。版だけ直して手元から送ると `oauth2Login` まで通った
- Lambda の失敗も版の古さによる見込みが高い（`docs/decisions.md` 2026-11-19 タスク 011）。版への追従はタスク 016 に起票した
- Node からの `oauth2Auth` は、この日だけで4回（Lambda 1、手元 3）

### 同日 21:44: Lambda から通った
- ユーザーの許可を得て、関数とロールを作り直し、版（`0.16.287`）を payload で渡して1回実行した → **ログインから牌譜の中身の取得まで通った**（すべて err=0）。AWS の IP からでも弾かれない
- 後片付け済み（関数・ロググループ・実行ロール・payload を消し、NotFound を確認）
- `docs/decisions.md` 2026-11-19 タスク 011

- これでタスクを閉じる。版への追従はタスク 016
