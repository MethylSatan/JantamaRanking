# 018 新しい主催者の過去分の取り込み

状態: todo / 依存: 006

## 目的
新しい主催者が Web サービスを使い始めるとき、それまでの友人戦も取り込みたいことがある。運営のアカウントから見える主催者の一覧（`fetchAccountInfoExtra`）は、種類ごとに最新50件で、さらに 2024-08 ごろより前の記録は入らない。それより古い対局を取り込む方法を決める。ちのリーグは今のところ欠けがないので、急がない。

## 読むべき資料
- `docs/architecture.md`（牌譜回収（タスク 006）、雀魂の WebGL 版の通信）
- `docs/local/018-new-host-history-notes.md`（ローカル限定。比べた具体）

## 作業範囲
- 主催者本人の一覧（`fetchGameRecordList` / `fetchNextGameRecordList`。ゲームの牌譜画面と同じ）が、どこまで遡れるかを確かめる。本人のログインが要る
- 本人の一覧の取り方を決める
  - Tampermonkey などのスクリプトを主催者のブラウザで動かし、ゲームの WebSocket に相乗りして一覧を取る。昔の2本は WebGL 版では動かないので作り直しになる（タスク 001）。liqi の定義は公開しないと決めている（`docs/decisions.md` 2026-11-19 タスク 017）ので、スクリプトに要る型の扱いを決める
  - 主催者に一度ブラウザでログインしてもらい、認証情報を預かって Node（`src/collector/`）から取る。スクリプトは要らないが、主催者のアカウントの認証情報を預かることになる
- 古い uuid（2020 年など）を `fetchGameRecordsDetail` に渡して、中身が返るかを確かめる（タスク 015 でも使う）
- 主催者の作業をどこまで許すか（`docs/product.md`「主催者に作業を求めない」）を整理する

## 完了条件
- 新しい主催者の過去分を取り込む方法と、主催者に頼む作業が決まり、`docs/decisions.md` に書かれている

## メモ
### 2026-11-20 起票（タスク 006 の後の調べ）
- 定義（11/19 版）の Lobby のメソッドのうち、相手を指定できて応答に uuid が入るのは `fetchAccountInfoExtra`（最新50件）と `fetchAccountState`（今打っている対局だけ）の2つだけ。本人の一覧（`fetchGameRecordList` / `fetchNextGameRecordList`）には相手を指定する項目がない。大会の記録（`fetchCustomizedContestGameRecords`）は大会の ID で取れるが、友人戦の部屋は対象外。相手の指定は項目名（`account_id` など）で探したので、別の名前のものは見落としているかもしれない
- 同じアカウントについて、本人が見た牌譜画面の一番古い友人戦と、別のアカウントから見た `fetchAccountInfoExtra` の一番古い友人戦を比べた。別のアカウントからは、件数が上限の50件に届いていないのに、約4年新しいところで止まっていた。→ 他人から見える一覧は、件数ではなく時期（2024-08 ごろ）で区切られているとみられる。本人の一覧は、それよりずっと前まで遡れる。具体は `docs/local/018-new-host-history-notes.md`
- → 2024-08 より前の分は、本人の一覧を遡るしかない。他の参加者の一覧から拾う方法は、2024-08 より後で主催者の50件から外れた分にしか使えない
