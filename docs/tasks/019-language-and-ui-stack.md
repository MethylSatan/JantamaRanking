## メモ
### 2026-11-20 完了
前提: 保守するのはユーザー本人。Node.js は多少経験があり、TypeScript はあまり分からない。Python・Go の経験はない。

#### サーバー側の言語
| 観点 | TypeScript（Node） | JavaScript（Node） | Python | Go |
|---|---|---|---|---|
| 本人の慣れ | △ 書き方は JS に型の注記を足しただけ | ◯ | ✕ | ✕ |
| 画面と集計のコードを共有できるか（期間の絞り込みは画面側） | ◯ | ◯ | ✕ 二重に書くか、絞り込みをサーバーに移す | ✕ 同左、または WASM |
| 雀魂の定義を実行中に読み込めるか（S3 の定義を使い、`err=151` のときだけ作り直す） | ◯ protobufjs が JSON の定義をそのまま読む | ◯ 同左 | △ protobufjs の JSON を記述子に変換する処理が要る | △ 同左（dynamicpb） |
| Lambda | 公式ランタイム。`.ts` の動かし方はタスク 010 で決める | 公式ランタイム。変換は要らない | 公式ランタイム | OS だけのランタイム（provided.al2023） |
| いまのコード（約2,200行、テストを含む）からの移行 | 不要 | 型の注記を外すだけ（機械的） | 全部書き直す | 全部書き直す |
| 誤りを見つける助け | ◯ `tsc` で型チェック | △ JSDoc ＋ `// @ts-check` で近いことはできるが、書き方が冗長 | △ | ◯ |

- Python と Go は、慣れ・画面とのコード共有・定義の読み込みの3点で不利なうえ、書き直しも要るので外した
- いまのコードは `erasableSyntaxOnly` で書いていて、使っているのは JS に型の注記を足しただけの範囲（enum などは使わない）。注記を読み飛ばせば JS として読める
- → TypeScript のまま続ける。JS ＋ JSDoc は、TypeScript の書き方をまったく覚えたくなくなったときの代わりの案として残す（移行は機械的にできる）
- Lambda の Node の版と、`.ts` をそのまま動かせるかは未確認（タスク 010）

#### 画面
要件: 運営向け（主催者の指定 → 候補の一覧 → 取り込む・対象外にする）と、閲覧者向けのランキング（並べ替え・期間の絞り込み）。小さな SPA で、`src/ranking/` を取り込んで使う。

| 観点 | フレームワークなし（Vite） | Preact（Vite） | Svelte（Vite） | Vue（Vite） |
|---|---|---|---|---|
| 覚えること | DOM の API だけ | JSX とフック。関数で書くので JS の知識がそのまま使える | 独自のテンプレートと runes | 独自のテンプレートと書き方の流儀 |
| 一覧の選択・並べ替え・絞り込みの書きやすさ | △ 表を描き直す処理を自分で書く | ◯ | ◯ | ◯ |
| 大きさ・依存 | 最小 | 小さい（約 4KB） | 小さい（コンパイル方式） | 中くらい |
| 情報や例の多さ | ◯ | ◯ React の情報がほぼ使える | ◯ | ◯ |

- Vite は、`src/ranking/` の `.ts` をそのまま取り込めるので、どの案でも使う
- → Vite ＋ Preact にする。フレームワークなしは、画面が本当に2〜3枚で済む場合の代わりの案
