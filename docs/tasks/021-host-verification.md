# 021 主催者の本人確認

状態: todo / 依存: 020、022

## 目的
複数の主催者に開放するときに、ログインした人が主催者本人（雀魂のアカウントの持ち主）であることを確かめる方法を決める（`docs/product.md` 未決事項）。誰に何を許すかは、タスク 022（権限の設計）で決める。

## 読むべき資料
- `docs/product.md`（利用者と操作、未決事項）
- `docs/decisions.md`（2026-11-20 タスク 014）
- `docs/local/008-terms-notes.md`、`docs/local/014-login-notes.md`（ローカル限定。雀魂の規約面、Discord の規約の要点）

## 作業範囲
- 雀魂のアカウントとの対応づけの方法を比べる
  - Admin が承認する（主催者がログインして雀魂の表示用 ID を申請し、Admin が画面で承認する）
  - 雀魂の自己紹介文に確認コードを書いてもらい、サーバーが確かめる。手元の定義では `Account` に `signature` があるが、他人の分を取れるかは未確認
- 開放すると雀魂への要求が増える。負荷の上限と、規約面の判断をやり直す

## 完了条件
- 本人確認の方法が決まり、`docs/decisions.md` に書かれている。実装タスクが起票されている

## メモ
- 2026-11-23: 権限の部分（Discord サーバーのロールを使うかを含む）は、タスク 022 に分けた
- 2026-11-25: タスク 022 で、ランキングの作成と雀魂アカウントの指定は Admin だけと決めた。本人確認は、Host に雀魂アカウントの指定まで任せるときに要る。それまでは Admin が確かめて指定すればよい
