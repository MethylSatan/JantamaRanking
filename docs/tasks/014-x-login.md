# 014 X ログインの調査（主催者への開放）

状態: done / 依存: -（当初は 013。2026-11-20 にログインを先に決めるため、013 より前に行った）

## 目的
複数の主催者に開放し、主催者が自分で取り込み・選定できるようにするための、ログイン方法を決める（`docs/product.md` 利用者と操作）。第一候補は X ログイン（ユーザーの希望）。

## 読むべき資料
- `docs/decisions.md`（2026-11-19）
- `docs/local/008-terms-notes.md`（ローカル限定。X API の料金の下調べ、開放時の規約面）

## 作業範囲
- X API で「X でログイン」（OAuth 2.0、`users/me`）をするときの料金と条件を、公式の価格ページで確かめる。2026-11 時点の下調べでは、無料枠は新規受付がなく従量課金という記事が多い（未確認）
- Cognito は X に対応していないので、つなぎ方を比べる（Lambda で OAuth 2.0 を自前で行う、Cognito のカスタム認証につなぐ、など）。X 以外（Google ログインなど）も候補に入れる
- 主催者が本人であることの確かめ方（雀魂のアカウントとの対応づけ）を決める
- 開放すると雀魂への要求が増える。負荷の上限と、規約面の判断をやり直す

## 完了条件
- ログイン方法と本人確認の方法が決まり、`docs/decisions.md` に書かれている。実装タスクが起票されている

## メモ
- 2026-11-20: ユーザーの希望で、013 の前にログインを先に設計した。結論は Discord（Cognito に OIDC でつなぐ。運営も主催者も）。X は採らない。決定と理由は `docs/decisions.md` 2026-11-20（タスク 014）、調査の具体（X の料金、Discord の discovery、規約の要点）は `docs/local/014-login-notes.md`
- X 以外の候補として、Cognito のメールとパスワード、メールのワンタイムコード、Discord、Twitch、Google、外部の認証サービスを比べた。Discord は OIDC の discovery を公開していて Cognito の標準の連携に乗る見込みで、API も無料
- 完了条件のうち、主催者の本人確認（雀魂のアカウントとの対応づけ）はユーザーの判断で後回しにし、タスク 021 に分けた。Discord サーバーのロールでの権限づけも 021
- 開放したときの雀魂への負荷と規約面の判断のやり直しも、021（開放の前）で行う
- 実装はタスク 020（Discord ログインの接続）に起票した
