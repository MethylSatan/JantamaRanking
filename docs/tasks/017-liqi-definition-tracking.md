# 017 liqi の定義への追従

状態: done / 依存: 016

## 目的
Node から雀魂と通信するには、liqi（protobuf）の定義が要る。今は 11/16 に旧クライアント（Laya 版）の経路（`version.json` → `resversion<ver>.json` → `liqi.json`、`0.11.x` 系列）で取った写しを使っている。WebGL 版が送る項目の一部（`requestConnection` の項目6、`oauth2Login` の `device` の中など）はこの定義に無く、手で補っている。雀魂の更新で定義が変わっても、Web サービスの定期取得が止まらないようにする。

## 読むべき資料
- `docs/architecture.md`（雀魂の WebGL 版の通信）
- `docs/tasks/016-client-version-tracking.md`（メモ。静的ファイルの取り方、UnityFS の展開）

## 作業範囲
- WebGL 版の中（`bundle_info_so.majset` が指すデータファイル、`jp-WebGL-release-*.data.gz` など）から定義を得られるかを調べる。まず手元のキャッシュと `local/probe/static-20261119/` を探す
- 旧クライアントの `liqi.json` が今も更新されているか、WebGL 版の通信と食い違いがないかを確かめる
- 定義を Lambda でどう持つかを決める（固定の写しを同梱する、ビルド時に取る、など）。`liqi.json` は雀魂のものなので、公開リポジトリには入れない
- 定義が合わなくなったことに、どう気づくか（デコードの失敗、`err=151` 以外のログインの失敗）を決める

## 完了条件
- 定義の得方・持ち方・壊れたときの気づき方が決まり、`docs/decisions.md` と `docs/architecture.md` に書かれている

## メモ
- 016 で、ユーザーの判断により、決めるのを後に回した

### 2026-11-19 WebGL 版の静的ファイルから定義を作れた
- 手元のキャッシュだけで調べた。`bundle_info_so.majset` の一覧にある `proto_config.bytes` は平文の JSON だったが、メソッドと型名の索引だけだった。項目の定義は、同じ一覧にある Lua の定義ファイル（protoc-gen-lua の生成物）にあり、暗号化されていた
- 復号するかどうかはユーザーに確認し、許可を得た。単純な暗号で、手元で復号できた。liqi.json と同じ形に変換すると、11/16 版・11/19 版とも protobufjs で読めた
- 記録済みの要求は、WebGL 版の定義ですべてバイト単位で再現できた（旧定義では `requestConnection` の項目6などが合わなかった）。違いは repeated の数値の packed だけで、送る側だけ揃えた
- 旧経路の liqi.json は、ユーザーの許可を得て取り直した（要求3回）。11/16 の写しと同じで、更新が止まっているとみられる。牌譜とログインに使う型は WebGL 版と同じ
- 持ち方と鍵の置き場所はユーザーと決めた。`err=151` のときにバージョンと一緒に作り直す。鍵は公開リポジトリに置かない。気づき方は、使っている型の番号・型の変化を作り直しのときに見て、変わっていたら採用せずに通知する（`docs/decisions.md` 2026-11-19 タスク 017）
- 具体（バンドルの中の場所、手元の道具、比較の数）は `docs/local/017-liqi-notes.md`
- Lambda への組み込みはタスク 006 で行う（依存に 017 を足した）
- 未確認: 同じバンドルにあるゲームの処理の Lua が同じ暗号か、`excel_pb`（設定の表）の使い道
