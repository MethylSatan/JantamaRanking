# 015 旧方式の牌譜（Drive）の移行

状態: done / 依存: 012、013

## 目的
旧方式で集めた 2022〜2024 年の牌譜を Web サービスに移し、旧スプレッドシートと同じランキングを出せるようにする。移行が済めば、旧スプレッドシートの役目を終えられる。

## 読むべき資料
- `docs/architecture.md`（旧集計、作り直し・取り消し・履歴）
- `docs/local/003-sheet-notes.md`（Drive のフォルダ、旧シートの場所。変更禁止）

## 作業範囲
- Drive のアーカイブ用フォルダ（四麻・三麻）と受け取り用フォルダの牌譜を、ユーザーに書き出してもらう（Drive の操作はユーザーが行う。旧シートと Drive は変更しない）
- 牌譜の json を S3 に入れ、作り直しの機能で対局の結果とランキングを作る。牌譜の形式は2種類ある（`docs/architecture.md`「入力の牌譜 json」）
- 旧方式では四麻か三麻かをフォルダで分けていた。移行後は `ratingc` で見分けるので、フォルダと食い違わないか確かめる
- 旧シートの試合結果・ランキングと一致するかを確かめる。違いがあれば理由を記録する（年別シートの12月31日の扱いなど、既知の違いは `docs/architecture.md`）
- 旧方式の主催者・企画を、Web サービスの企画としてどう登録するかを決める
- 旧方式の牌譜にはアカウント ID が無く、集計は名前でまとまる（タスク 012）。新方式の対局（ID あり）と同じ人として数えるには、名前と ID の対応づけが要る。やり方（対局の中身を雀魂から取り直す、手で対応表を作る、など）を決める
- 旧方式の牌譜の期間と、新方式（主催者の友人戦一覧。種類ごとに最新50件）の一番古い対局の間に、どちらでも取れない期間がないかを確かめる（タスク 006 の実地確認で、主催者の一覧は既に50件に達していた。具体は `docs/local/006-collector-notes.md`）
- 名前と ID の対応づけで「対局の中身を雀魂から取り直す」なら、旧方式の牌譜の `ref`（uuid）をタスク 006 の `fetchHeads` に渡せば、参加者の内部 ID つきの head が取れる見込み（古い uuid で返るかは未確認。1回100件まで）
- 旧方式の牌譜の手元の写し（アーカイブの全量。受け取り用フォルダの分は含まない）と、旧シートとの突合のスクリプトは、タスク 012 で `local/legacy/`・`local/verify-012/` に置いた。牌譜 → 試合結果 → ランキングが旧シートと一致することは確かめ済み（`docs/local/012-verify-notes.md`）

## 完了条件
- 旧シートにある全対局が Web サービスに入り、ランキングが旧シートと一致する（違いは理由つきで記録されている）

## メモ
- 2026-11-27: 本番のランキング「ちのリーグ」を作り、旧方式の全953局（四麻405・三麻548）を「取り込み済み」で入れた。作り直しのジョブで953件とも S3 の牌譜から読め、変わったものは0件。具体（ランキング ID・名前）は `docs/local/015-migration-notes.md`
- 名前と ID の対応づけ: 旧方式の牌譜の `ref` で雀魂から head を取り直した（`docs/decisions.md` 2026-11-27 タスク 015）。2022-08 の古い uuid も返った。ログイン2回（試しの6件、残りの946件）、牌譜の要求は約20回（50件ずつ）
- 手順は `src/migrate/legacy.ts`（`fetch` → `compare` → `upload`）。入出力は `local/legacy/`（取り直した head は `heads/`、突き合わせの結果は `out/compare.txt`）
- 旧方式の牌譜1件は、牌譜を手で作った対局だった（uuid がすべて0。雀魂に無い）。参加者の名前がほかの対局でそれぞれ1つの ID に結び付くので、旧牌譜の点数・pt とその ID で head を作って入れた（ユーザーの判断）。head に `legacyManual` を付けて、手で作ったことを残した
- 突き合わせ: 953局とも、終了時刻・四麻/三麻（フォルダ・`ratingc`・head の3つ）・席ごとの名前・点数・pt・順位が一致した。AI の席には ID が無い（新方式と同じ）。同じ名前で別の ID の人はいなかった
- 旧シートとの違い: 改名した人（1つの ID に複数の名前）が8人いて、ID でまとめると1人になる。人数は四麻の全期間 158→152・2023年 89→87・2024年 114→113、三麻の全期間 155→146・2023年 89→86・2024年 114→111（2022年は同じ）。まとめた人の値は、名前ごとの値の合計と一致する。名前でまとめ直すと、どの年も人数が旧シートと一致する（値の一致はタスク 012 で確認済みで、対局の中身は上のとおり同じ）
- 公開のランキングの JSON は、手元の head から作った結果と完全に一致した。閲覧の画面（Playwright）で四麻2023年・三麻2024年の表が出ることを確かめた
- 四麻か三麻か: 旧方式のフォルダと `ratingc` と head（席の数）は全件で一致した
- 受け取り用フォルダ（Drive）: 書き出した zip に、`archives` の外のファイルは無かった。空だったとみる
- 主催者・企画の登録: 旧方式の対局は、新方式と同じランキング「ちのリーグ」に入れた（ユーザーの判断）。閲覧の画面で年・期間を選べば、旧シートの年別の表にあたるものが出る
- 新方式の一覧との間の欠けの確認と、ちのリーグへの主催者の雀魂アカウントの指定は、タスク 030 に移した（表示用 ID が手元に無い。head にも入っていない）
