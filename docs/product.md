# プロダクト要件

## 目的
雀魂の友人戦の牌譜を集計し、メンバーごとの成績をランキング形式で見られるようにする。
元は、Vtuber の東風乃ちのさんのメンバー限定友人戦向けに作った。

## 目指す形
できれば、**牌譜の取り込みと集計対象の選定を、利用者がセルフサービスで行える Web サービス**にする（2026-11-16）。
- 雀魂との通信はサーバー側で行う。サービス用の運営アカウントで、Node から直接つなぐ方式（L2）が前提になる
- ブラウザでログインしてゲームの接続に相乗りする方式（L1）は、L2 が不可能な場合の最終手段とする

## 対象
- 主催者: 友人戦を開催する人
- 運営: 牌譜を取り込み、ランキングに反映する人（このツールを動かす人）
- 閲覧者: 友人戦の参加者（ランキングを見る人）
- 主催者・閲覧者はエンジニアではない想定。コマンド操作や環境構築を前提にしない
- 需要は東風乃ちのさんのコミュニティ次第。汎用ツールとしての保証はしない

## 機能要件（半自動フロー）
2026-11 時点で、雀魂の WebGL 化により 1・2 の旧方式（主催者が Tampermonkey で取得）は動かない。運営のアカウントから主催者の友人戦を取る方式に置き換える（タスク 005・006）。主催者の作業は不要になる見込み。
1. 主催者の友人戦の一覧を取得する（運営のアカウントで、主催者の対局記録から）
2. 牌譜データを取得する（同上）。主催者の友人戦には取り込み対象でないものもあるので、自動では取り込まない。候補の一覧から、取り込む対局を選ぶ（Web サービスにするなら、利用者が画面で選ぶ）
3. 選んだ対局の結果を、Web サービスに取り込む（旧方式: 牌譜を Google Drive にアップロードし、GAS でスプレッドシートに投入していた。2026-11-19 にやめると決めた）
4. Web サービスで集計し、ランキングを Web ページで見せる。CSV などでの書き出しは用意しない（旧方式: スプレッドシートで集計）

### 利用者と操作（2026-11-19）
- 当面、取り込み・選定の操作は運営だけが行う。ログインが要る
- 閲覧者はランキングを見るだけ。ログインは求めない（推測されない URL、検索には載せない）
- 認証が解決できれば、複数の主催者に開放し、主催者が自分で取り込み・選定できるようにしたい
- ログインは Discord で行う。運営も主催者も同じ（2026-11-20、タスク 014。接続はタスク 020）

## 非機能要件
- 雀魂のサーバーに過度な負荷をかけない
- アクセストークンなどの認証情報を公開しない
- 主催者に作業を求めない。運営が手作業で回せる手間に収まる
- 手順は、非エンジニアがブラウザ操作中心でこなせること

### 旧方式（スプレッドシートと Drive）の利点を引き継ぐ（2026-11-19）
旧方式を採った理由を、Web サービスでも満たす。
- **作り直せる**: 牌譜の生の json をすべて残し、そこから対局の結果とランキングを全部作り直せる。牌譜を誤って消したり上書きしたりしても戻せる（旧: Drive に全牌譜を残し、アーカイブから全量を取り込み直す）
- **誤りを戻せる、履歴が残る**: 取り込みの誤りは、対局を対象外にする1操作で戻せる。データは消さない。誰が・いつ・どの対局を・どう変えたかを残す。過去の時点の状態にも戻せる（旧: 行を消す、シートの編集履歴）
- **見る人が並べ替え・絞り込みできる**: 列ごとの並べ替えと、名前・期間・四麻か三麻かでの絞り込みを画面で用意する。それ以上の機能は、見る人の要望を受けて画面に足す。CSV などでの書き出しは用意しない（旧: スプレッドシートで自由に操作）

## スコープ外（現時点）
- 完全自動化（雀魂へのログインを含む）。ただし Web サービスにする場合、サーバーが運営アカウントでログインし続ける仕組みは必要になる（タスク 007・008）
- 友人戦以外（段位戦・大会戦）の集計

## 未決事項
- 複数の主催者に開放するとき、主催者が本人であること（雀魂のアカウントの持ち主であること）の確かめ方と、権限の決め方（タスク 021）
- 決定済み（2026-11-20、タスク 014）: ログインは Discord（Cognito に OIDC でつなぐ）。X ログインは料金と、Cognito に直接つなげないことから採らない
- 運営アカウントの認証情報の取り直しの手順と頻度（タスク 009）
- 決定済み（2026-11-19、タスク 012）: ランキングに載せる内容は旧シートの機能をすべて引き継ぐ（全期間、期間での絞り込み、今月参加済み、今月まだ打っていない人）。集計のルールは固定（累計pt の大きい順）。月・年は朝6時で区切る。詳細は `docs/architecture.md`「集計（Web サービス）」
- 決定済み（2026-11-19、タスク 008）: GAS とスプレッドシートはやめて Web サービスで集計する。置き場所は AWS（無料枠中心）。構成は `docs/architecture.md`。旧方式の利点を引き継げることを確かめた（上の非機能要件、`docs/decisions.md` 2026-11-19 タスク 003 の後）
